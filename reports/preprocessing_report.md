## 3. Split & class distribution (Parts B & G)

- Split: **stratified 80/20**, random_state=42 (matches dataset authors' recommended 80/20)
- Rows: 3539 train / 885 test

| Set | N | Dropout | Enrolled | Graduate |
|---|---|---|---|---|
| full | 4424 | 1421 (32.1%) | 794 (17.9%) | 2209 (49.9%) |
| train | 3539 | 1137 (32.1%) | 635 (17.9%) | 1767 (49.9%) |
| test | 885 | 284 (32.1%) | 159 (18.0%) | 442 (49.9%) |

**Majority-class baseline (Part G):** a constant predictor that always outputs `Graduate` achieves **49.9% accuracy** on this distribution. Any Phase-4 model must beat this honestly — and still show usable recall on `Dropout`/`Enrolled`, which accuracy alone would hide. Class weights are supported later; resampling is deferred (target distribution untouched in Phase 3).

## 9. Leakage checks implemented (Part J)

- target column inside X → rejected
- unexpected / missing / duplicate columns → rejected
- H1 frame containing semester columns → rejected
- target values ≠ {Dropout, Enrolled, Graduate} → rejected
- class-proportion drift > 1pp between splits → rejected
- train/test index overlap → rejected
- scaler statistics ≠ training means → rejected (fit provenance)
- unseen category at transform time → must not raise (handle_unknown='ignore')
- Phase-2 horizon policy (`feature_sets.validate`) re-run on every load
